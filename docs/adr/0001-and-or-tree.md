# ADR 0001: 探索木を AND-OR ツリーで表す

- 状態: 採用
- 日付: 2026-10-17

## 背景

E.T.H.A.N. の中心は「探索的」なオーケストレーションである。タスクの分解（階層）と、別案の試行（探索）の両方を扱う必要がある。

## 決定

探索木を AND-OR ツリーで表す。

- `Task` は OR ノードとする。直接実行するか、候補プランのどれか 1 つで解く。
- `Plan` は AND ノードとする。サブタスクをすべてこなす必要がある。
- プラン内のサブタスクは依存関係を持つ DAG とし、依存のないものは並列に実行する。

プランナーは 1 回の LLM 呼び出しで、直接実行するかどうかの判定と、K 個の候補プランを構造化出力で返す。最大深さに達したタスクと、ノード数の上限を超えた後のタスクはプランナーを呼ばずに直接実行する。

## 検討した代替案

- 子ノードが「別案」か「部分」かを区別しない単一種別のノード。評価関数の設計が難しくなり、刈り込みの単位も曖昧になる。
- 分解のみを木にし、探索は葉での複数回試行に限る。分解の仕方そのものを探索できない。
- 事前に定義する静的 DAG。動的な分解ができず、"Exploratory" の趣旨に合わない。

## 結果

- 探索（OR）と分解（AND）が型として分かれ、トレースから「どの案をなぜ選んだか」を追える。
- 依存関係が壊れた案（循環、存在しない ID、空のプラン）は破棄する。全案が破棄されたら直接実行に切り替える。
