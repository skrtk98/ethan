# ADR 0006: プロバイダアダプタの要件と、OpenAI・Ollama への対応

- 状態: 採用
- 日付: 2026-10-18

## 決定

- OpenAI 用のアダプタを `ethan/openai` に置き、公式 SDK（`openai-go/v3`）の Responses API で呼ぶ。既定のモデルは `gpt-5.5` とする。
- Ollama 専用のパッケージは作らない。Ollama は Responses API を実装しているので、`openai.WithBaseURL("http://localhost:11434/v1/")` で向け先を変えて使う。
- アダプタが必ず実装するもの:
  - テキスト、クライアント側ツールの呼び出し、構造化出力（`Request.Output`）。どれもプロバイダの機能でネイティブに実装する。コア側に「テキストから JSON を拾う」ような代替処理は持たない。
  - 失敗した呼び出しでも、課金された使用量は `Response.Usage` で返す。
  - キャンセルされた `ctx` では呼び出さず、`context.Canceled` を返す。
- アダプタごとのオプションにするもの: Web 検索などのサーバー側ツール、推論の強さ（effort）、キャッシュ。コアの抽象には入れない。
- 使用量は入力と出力のトークン数に揃える。キャッシュの読み書きは、プロバイダが報告する範囲で `CacheReadTokens` と `CacheWriteTokens` に内訳として入れる（`InputTokens` に含む）。
- 上記の要件は `ethantest.TestModel` の適合テストで確かめる。各アダプタは、自分のプロバイダの API を真似た偽の HTTP サーバーを用意して、このテストを走らせる。

## OpenAI アダプタの方針

- 状態を持たない。`store=false` とし、会話の履歴は毎回送る。推論の中身は `reasoning.encrypted_content` で受け取り、出力項目ごと `Part.Raw` に保持して送り返す。
- 構造化出力は `text.format` の JSON スキーマを strict モードで使う。コアのスキーマは strict の条件を満たしている。クライアント側ツールは strict にしない。利用者のスキーマが条件を満たすとは限らないためである。
- 失敗したツールの結果は、出力の先頭に `error: ` を付けて渡す（Responses API にはエラーの印がない）。
- 拒否（`refusal`、`content_filter`）は `ethan.ErrRefused` を包んだエラーを返す。出力の上限で切れた応答は、テキストでも構造化出力でもツール呼び出しでも、`ethan.ErrTruncated` を包んだエラーと使用量を返す。エンジンはどちらも完成した答えとして扱わない。`Request.MaxOutputTokens` が 0 のときはアダプタの既定値に任せる。
- Web 検索の回数の上限には `max_tool_calls` を使う。これはサーバー側ツールの呼び出し全体に効く。

## モジュール構成

開発中は 1 つのモジュールに各社の SDK を並べる。コアだけを使う人の `go.mod` にも SDK が間接依存として現れるが、コアのコードは SDK を読み込まない。最初のタグを付ける前に、プロバイダごとにモジュールを分けるかを決め直す。

## 理由

- 2 つ目のアダプタを書くことで、`Model` の抽象が足りるかを確かめられた。足りない点はなかった。`Part.Raw` は、プロバイダ固有の項目（思考ブロック、推論、サーバー側ツール）をそのまま往復させるのに十分だった。
- Responses API は Web 検索、構造化出力、推論の強さを 1 つの API で扱える。Ollama も同じ API を実装しているので、ローカルモデルでの試験を無料で行える。

## 結果

- エージェントごとに別のプロバイダのモデルを持たせられる。ただし `Part.Raw` は他のプロバイダに渡せないので、1 つのタスクの中ではモデルを替えない。
- Ollama では Web 検索を使えない。
