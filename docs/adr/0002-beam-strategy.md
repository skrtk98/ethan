# ADR 0002: 既定の探索戦略を局所ビームにする

- 状態: 採用
- 日付: 2026-10-17

## 決定

`Strategy` インターフェースで探索戦略を差し替え可能にし、既定を `BeamStrategy` とする。

1. 候補プランが幅 B より多いときだけ、全候補を実行前に評価して並べ替える。
2. 上位から B 案ずつ並列に実行する。
3. その組で成功した案が複数あれば結果を評価し、最良の 1 案を採用する。残りの未実行案は刈り込む。
4. その組が全滅したら次の B 案に進む（バックトラック）。全滅の原因がすべて予算切れなら打ち切る。

既定値は K=3（候補数）とする。幅 B は深さで変え、ルートで 2、それより深いところで 1 とする（`Width` と `DeepWidth`）。

## 理由

- 並列性と分かりやすさのバランスが良い。
- 選択肢がないときは評価を呼ばないので、LLM 呼び出しを節約できる。
- 大域 best-first や MCTS は、同じインターフェースの上に後から追加できる。

## 改訂（2026-10-17）

当初は全ての深さで B=2 だった。実 API での試験では、深さ 0 と 1 の両方で 2 案を並列に実行したため、Web 検索をする末端のタスクが 29 個に膨らみ、予算 30 万トークンを使い切った。並列に試す案は、その下の部分木のコストをまるごと倍にする。そこで、案を並べて比べるのはルートだけにし、深いところの別案はバックトラック用に残すことにした。

あわせて、プランナーに深さ・残りの深さ・残りの予算（タスク数とトークン数）を伝え、深いところや予算が少ないときは直接実行を優先するよう指示する。

## 結果

評価の失敗は致命的にしない（スコアなしとして扱う）。評価は順位付けのための補助であり、評価だけが失敗して成功した結果を捨てるのは損失が大きいためである。
