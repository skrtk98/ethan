# ADR 0004: 予算超過時はそれまでの最良の結果を返す

- 状態: 採用
- 日付: 2026-10-17

## 決定

`Budget` に次の上限を持たせる。キャンセルとタイムアウトは `context.Context` で扱う。

| 項目 | 既定値 | 超過時の挙動 |
|---|---|---|
| `MaxDepth` | 2 | その深さのタスクは分解せず直接実行する |
| `MaxNodes` | 40 | 以降のタスクは分解せず直接実行する（ソフトな上限） |
| `MaxTokens` | 無制限 | 以降のモデル呼び出しは `ErrBudgetExhausted` で失敗する |
| `MaxConcurrency` | 4 | 同時に実行するモデル呼び出しをセマフォで制限する |

トークン予算が尽きたときは、次のようにして「それまでの最良の結果」を返す。

- 統合が予算切れで失敗したら、サブタスクの結果を見出し付きで連結したものをプランの結果とする。
- ビームの組の中で成功した案があれば、それを採用する。
- `Result.Exhausted` で予算切れを知らせる。何も得られなかったときは `ErrBudgetExhausted` をラップしたエラーを返す。

## 結果

トークン予算の判定は呼び出し前に行うため、並列に走っている呼び出しの分だけ上限をわずかに超えることがある。
